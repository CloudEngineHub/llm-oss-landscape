1. Opening

Hi everyone, thanks for having us here. I will keep this fairly informal.

A full landscape report would be too much for this slot, so I will pick a few signals we are seeing in open source and connect them to the AI readiness questions that matter for financial services.

Near the end I will also briefly introduce one protocol idea from Alipay+, AMP, because agentic commerce is a very concrete place where all these readiness questions show up immediately.

The main thought is simple. Agentic AI is starting to look like infrastructure. For finance, the useful version is the one we can control, audit, afford, and put into real workflows.

2. Agents as software users

The change I would start with is simple, and I believe this group has discussed it a lot already: agents are becoming users of software.

Traditional software assumes a human is present at the interface. The human reads, clicks, confirms, and takes responsibility.

Agents show up differently. They may call an API directly, run a tool in the background, or continue after the user has left the session.

That changes the control question. If the actor touching the system is an agent, what does the system need to know before it lets the agent act?

This connects naturally to the FINOS AI Governance Framework. A lot of AI risks become sharper once the system can act, especially around traceability, versioning, approval, and recovery.

3. Open-source signals

One thing we found interesting is that stronger models did not make software smaller.

GitHub keeps growing. Hugging Face also feels less like a model showcase now and more like a factory floor. A model gets released, and then the community immediately starts adapting it: lighter versions, local versions, domain versions, runtime-specific versions.

In the first four months of 2026, OpenDigger observed more than 13 million active developers and more than 27 million active repositories. Hugging Face reached 2 million public models, with more than 540 thousand added by May 2026 alone.

The software around the model now carries more responsibility. Permissions and operating cost are two obvious examples.

FINOS already has mature work in those less glamorous layers. They decide whether a capable model can actually be used in production.

4. Automation in collaboration

Another signal we care about is automation inside collaboration.

Bots are not new. We have had CI and dependency bots for years. What feels different now is that some AI tools can read the change, comment on it, and even propose a patch.

In the first four months of 2017, only 112 bot or app actors were active in the GitHub event stream. In the same period in 2026, the number reached 17,285. The first four months of 2026 also already doubled the same period in 2025.

In our 226 Agentic AI project set, we found 563,973 developers or automated accounts participating between January and the end of April 2026. I would read that number as a signal that automation is becoming part of the collaboration network.

For financial services, it changes the control question. If an agent can submit a payment instruction, the system needs to know who authorized it and what evidence was recorded.

This is where CALM feels relevant. Once agents start touching real systems, architecture cannot live only in diagrams and human memory. Some of it has to become machine-readable.

5. Three-layer stack

In our landscape, we organize the ecosystem into three layers.

Agent Infra is the working environment for agents. It gives them context, tools, and boundaries.

Model Infra makes model capability reliable enough to operate. Routing and cost are two important parts of that layer.

Models still define the capability boundary. In real deployments, teams often choose different models for different tasks and risk levels.

For finance, model benchmarks tell only part of the story. The execution stack matters too.

6. Runtime signals

The easy story is that coding agents are hot. That is true, and it is also a little too easy.

The more useful signal is that the runtime around agents is heating up too. MCP is one example. Observability is another. Gateways are also becoming important because teams need a controlled way to reach different models.

In our classification of 226 projects, coding-agent projects reached 78. MCP-related projects reached 59. Memory and observability were also large labels in the set.

That feels like a production signal. People already know how to build a demo agent. The next question is what happens when it fails inside a real workflow.

This is a nice bridge to FINOS Fluxnova. Workflow orchestration in finance already deals with process visibility, approvals, and end-to-end execution. Agentic workflows need that discipline.

7. Controlled autonomy

My favorite phrase here is controlled autonomy.

If we only maximize autonomy, it becomes hard for a bank or regulated institution to adopt. If we build control into the architecture, agents become much more useful.

The first questions are very practical. Who approved this? What was the scope? Where is the evidence? Those answers decide whether the system can be trusted.

FINOS can help make these controls reusable. One useful output would be a controlled-agent reference pattern mapped to the AI Governance Framework and described through CALM.

The implementation will differ by firm. The approval and evidence questions are shared.

8. FINOS project map

When I looked at the leading FINOS projects, what stood out is that they already cover many of the pieces agentic systems keep needing.

The AI Governance Framework gives a risk and mitigation language. Fluxnova is close to workflow orchestration and process visibility. CDM has the financial industry's habit of making activities machine-readable. CALM brings architecture-as-code. HPC is close to the compute and cost problem.

A concrete reference pattern could connect several of these projects. CALM could describe the architecture. Fluxnova could represent the workflow and its approval points.

The risk controls could map to the AI Governance Framework. CDM is relevant where financial intent or transaction evidence needs a shared representation.

9. Token cost

For a chatbot, token cost can look like usage cost. For an agent, tokens start to look like production material.

Think about a research or coding agent. One user request can turn into many model calls before the user sees the final result. It may retrieve documents, call tools, revise an answer, run checks, and ask another model to evaluate the result.

That makes model routing a governance capability. The question becomes: for this task and this risk level, which model should we use, and how much are we willing to spend?

RouteLLM showed that routing can keep quality close to a strong model while cutting cost to less than half on some benchmarks. IPR reported a 43.9 percent cost reduction in a cloud deployment setting. The exact numbers are less important than the direction: model choice is becoming operational policy.

FINOS HPC is relevant here. Financial institutions already know how painful large compute workloads can be. AI inference and agent workloads are starting to need the same discipline.

10. Model portfolios

The model layer is still the source of capability for the whole stack. But it is getting harder to talk about a single winner.

A coding agent and a private local workflow may need very different models. A financial workflow may also need domain knowledge and policy constraints around the model.

The useful question is which model fits this task, this risk level, and this budget.

Open components make more of that choice inspectable and adaptable.

11. AMP bridge

Let me make this concrete with commerce.

Traditional payment systems have a familiar trust moment: a person sees the transaction and taps confirm.

In agent-assisted commerce, the user may say: find me a flight under this budget, book it if the timing works, and tell me later. The user is still the source of intent, but the agent may move the transaction forward later.

That creates a trust gap. A merchant or wallet needs to know whether the agent was really authorized, what budget or conditions the user approved, and whether the final payment stayed inside that scope.

The AI Governance Framework can describe the control problem here. CDM is relevant because the financial intent and transaction evidence need a machine-readable form.

12. AMP protocol

This is where AMP comes in.

AMP is the Agentic Mobile Protocol, an open-source application-layer trust protocol developed by Alipay+ for agentic payment scenarios.

AMP sits above the existing payment rails. The rails still move the money; AMP tries to carry the missing trust context around the agent.

The idea is simple: when an agent helps with a transaction, the rest of the ecosystem should not have to guess what the user approved. The approval, scope, and evidence should travel with the flow.

The whitepaper describes AMP on top of the Alipay+ global wallet gateway, which connects more than 2 billion user accounts through 50 mobile payment partners to more than 150 million merchants across more than 220 markets.

13. AMP patterns

For a first discussion, I would keep AMP to two patterns.

The first is familiar: real-time approved payment. The user is online, the agent prepares the order, and the user confirms the exact payment.

The second is newer: pre-authorized intent. The user sets the goal and budget first. The agent can continue later, but the payment only goes through if it still matches what the user approved.

The payment screen is only the visible part. The harder question is how intent, delegation, and evidence travel through the transaction.

There are several specific links to FINOS work. AMP controls could be mapped to the AI Governance Framework. A payment flow could be described in CALM and tested as a Fluxnova workflow. CDM may also offer useful patterns for representing intent and transaction evidence.

14. AMP collaboration

Agentic commerce touches too many parties for one company to define the whole answer.

Banks need to apply risk policy to delegated intent. Wallets retain the user's approval and payment controls. Card networks and acquirers see authorization and merchant-side integration. Agent platforms carry the original intent and transaction context.

Those are the participants that could test AMP against real integration requirements.

A separate AMP session could go into the protocol flow, the two payment modes, and the open questions for implementers.

15. InclusionAI

Let me close by placing this in the bigger InclusionAI picture.

Our belief is that intelligence should be something more people can understand, use, adapt, and improve.

That is why InclusionAI works across the stack: models, model infrastructure, agent infrastructure, and real service scenarios.

For financial services, this matters because the industry cares deeply about infrastructure that can be inspected and governed. Open source is one way to make intelligent infrastructure easier to review, deploy, and improve together.

16. Open homes

One concrete example is AReaL. It is our RL infrastructure for reasoning and agentic models, and it is now in the PyTorch Foundation ecosystem.

Open governance gives infrastructure a path to earn trust.

A future foundation donation is also under consideration for ASystem, our agent runtime stack.

The relevant FINOS links are concrete. HPC covers training and inference workloads. CALM can describe controlled-agent architecture. AI Governance can connect evaluation evidence with risk controls.
