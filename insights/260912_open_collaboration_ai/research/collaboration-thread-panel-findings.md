# 统一线程样本：真人响应与 PR 修改循环

## 这组数据回答什么

这里继续使用冻结 Top 100，并只比较贯穿 2025—2026 年的同一组 55 个仓库。每个仓库、每年最多抽取 50 条 Issue 或 PR；不按仓库流量加权，每条线程只计算一次。全量队列和 90 天合入结果以 GitHub 全量计数为准；这组样本只用来观察完整时间线里谁先响应、是否进入修改循环。

## 真人响应

- 出现具名 Agent 或 App 的线程：19.9% → 46.1%。
- 七天内收到非作者、非自动化账号响应的线程：61.2% → 54.3%。
- 七天内收到仓库 Owner、Member 或 Collaborator 响应的线程：37.1% → 31.1%。
- 30 天内解决的 Issue：48.2% → 53.5%；30 天内解决的 PR：87.8% → 80.3%。

## PR 如何进入修改循环

- 有公开 review 记录的 PR：68.8% → 73.9%。
- 至少收到一次正式 changes requested 的 PR：3.6% → 4.1%。
- 收到修改要求后又提交代码的 PR：70.5% → 75.9%。
- 两轮或更多“修改要求—新提交”循环的 PR：0.2% → 0.7%。

这里的“轮”不是 review 条数。第一次 changes requested 记为一轮；作者提交新代码后再次收到 changes requested，才进入下一轮。这样更接近读者所理解的修改迭代。
