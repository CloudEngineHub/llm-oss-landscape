# 10 个代表仓库：协作方式如何随项目阶段变化

这不是再做一遍 100 仓库的平均数。这里选了 10 个差异明显的仓库，每个仓库分别抽取创建后 120 天、2025 年最后四个月和 2026 年最近四个月的 30 条 Issue / PR，然后读取完整公开时间线。

## 先说结论

从 2025 年最后四个月到 2026 年最近四个月，没有一项指标在 10 个仓库的配对比较并经过多重比较修正后达到 q < 0.05。能看到方向，但还不能把短期变化说成普遍规律。

## 变化最大的指标

- **首次维护者回复中位小时数**：152.3 小时 → 89.1 小时；5 个仓库上升、5 个下降；p=0.7480，q=0.8056。
- **首次人类回复中位小时数**：49.8 小时 → 19.3 小时；5 个仓库上升、5 个下降；p=0.5762，q=0.8056。
- **Agent 参与线程**：35.7% → 53.3%；6 个仓库上升、3 个下降；p=0.0391，q=0.2734。
- **维护者账号参与**：50.7% → 35.0%；1 个仓库上升、6 个下降；p=0.0625，q=0.2917。
- **外部贡献者发起 PR**：65.7% → 80.1%；5 个仓库上升、3 个下降；p=0.1719，q=0.4193。
- **30 天内合入 PR**：64.4% → 54.4%；1 个仓库上升、7 个下降；p=0.1797，q=0.4193。
- **Agent 参与回复**：29.0% → 38.3%；7 个仓库上升、2 个下降；p=0.3789，q=0.6631。
- **回复只有自动化账号**：26.3% → 35.3%；6 个仓库上升、2 个下降；p=0.3047，q=0.6094。

## 仓库之间不是同一种变化

- **LangChain**：可见 Agent 参与从 10.0% 升到 80.0%；维护者账号参与从 80.0% 降到 20.0%。这是值得逐条读线程的高优先级案例，但 30 条样本不能直接解释成 Agent 替代维护者。
- **Coder**：可见 Agent 参与从 6.7% 升到 46.7%；30 天内合入 PR 反而从 69.6% 升到 84.2%。它是“Agent 增多不必然拖慢合入”的反例。
- **PyTorch**：可见 Agent 参与从 3.3% 升到 26.7%；维护者参与保持在 70.0%。传统治理并没有因为 Agent 出现就自动撤掉人的 gate。
- **Claude Code**：两个近期阶段的概率样本都没有抽到 PR，因此不能估计 review 或合入变化；Issue 中只有自动化账号回复的比例从 73.3% 降到 36.7%。这里应把“公开协作面如何设计”作为案例问题，而不是硬算一个 PR 效率。

## 这轮实验能回答什么

- 它能看同一个仓库在不同阶段是否改变了回复、review、维护者介入和 Agent 可见参与方式。
- `30 天内关闭` 和 `30 天内合入` 只使用已经获得完整 30 天观察期的线程，避免把 2026 年 8 月刚创建的线程误判为 backlog。
- 它仍然不能识别普通开发者账号背后的未披露 AI 使用，也不能把时间上的同时变化直接解释成 Agent 导致的变化。
- 每个仓库每阶段 30 条适合找模式和反例，不适合对单个仓库给出精确排名。需要回到具体线程逐案解释时，应从这张概率样本继续做案例编码。
